What QC produces

Input, output, and what actually changes

QC does not modify your measurements. It appends columns. Longitude, latitude, velocity and bearing come out byte-identical; what you gain is a verdict per row, plus a header block recording the thresholds that produced it.

LOCAL_BASE/<institution>/<SITE>/raw/<Pattern>/RDLx_SITE_YYYY_MM_DD_HHMM.ruv │ 18 columns · no flags ▼ qc_radial_file() — seven tests + rollup LOCAL_BASE/<institution>/<SITE>/qartod/<Pattern>/RDLx_SITE_YYYY_MM_DD_HHMM.ruv 26 columns · Q201–Q207 + PRIM

The output file gains a self-documenting header:

%QCFlagDefinitions: 1=pass 2=not_evaluated 3=suspect 4=fail 9=missing_data
%QCTest: qc_qartod_maximum_velocity (Q202) - Test applies to each row.
         Thresholds=[ high_vel=140 (cm/s) max_vel=190 (cm/s) ]
%TableColumnTypes: ... BEAR VELO HEAD SPRC Q201 Q202 Q203 Q204 Q205 Q206 Q207 PRIM

That header is the real deliverable. Six months from now it tells you exactly which settings produced a given flag — flags without their thresholds are not defensible.

Never write into raw/

to_ruv() calls os.remove() on its target before writing. If the write then fails, the file is gone and nothing replaces it. The overwrite=False guard compares the resolved source path against the filename string as passed, so a relative path defeats it. Keep the raw archive read-only.

Flag values

IOOS QARTOD convention — used by every column

FlagMeaningWhat it tells you
1 pass The test ran and the value is good.
2 not evaluated The test could not run here — most often Q206, where a cell has no counterpart in the previous hour. Neither good nor bad.
3 suspect Outside normal but not impossible. Keep, but do not trust blindly.
4 fail Reject. This is what the cleaned output strips.
9 missing data No value present to test.
A real per-file distribution reads as a count per flag — e.g. Q206 {1: 371, 2: 61, 3: 9, 4: 12} means 371 rows passed, 61 could not be evaluated, 9 were suspect and 12 failed, out of 453 rows.

The seven tests

Four need per-site parameters · three do not

Grouped by the question they ask: Q201 and Q204 ask whether the file is usable at all; Q202 and Q203 ask whether a vector is physically possible; Q205 and Q206 ask whether it agrees with its neighbours in space and time; Q207 asks whether the instrument is still aimed correctly.

Q201Whole file

Syntax · QARTOD Test 6

Is the file structurally intact?

Header present, column counts consistent, %TableRows matching the actual row count. Catches truncated transfers and interrupted writes — including the partial files produced by the to_ruv() hazard above.

no parameters — never needs tuning
Q202Per row

Maximum Velocity · QARTOD Test 7

Is this speed physically plausible?

Surface currents rarely exceed 1–2 m/s. Beyond max_speed the row fails; between high_speed and max_speed it is suspect. Catches Bragg peak misidentification, where the algorithm locks onto a ship echo or interference instead of the sea surface.

high_speed — suspect above this (cm/s) · p99 of observed |VELO|
max_speed  — fail above this (cm/s) · capped at %CurrentVelocityLimit

The cap matters: the radar physically cannot report a current faster than its own %CurrentVelocityLimit, so any value sitting at that limit is a processing artefact rather than water movement. Your sites range from 80 to 250 cm/s, which is why a single default is wrong.

Q203Per row

Valid Location · QARTOD Test 8

Is this cell over water?

Checks each lat/lon against a bundled coastline shapefile. Radars report all around the compass, and anything inland is geometrically impossible.

use_mask — default True
res      — 'high' or 'low' coastline resolution

This is normally the largest source of 4 flags and that is correct behaviour, not a misconfiguration. OBSP fails 42% of rows because 42% of its cells point inland. Verify by breaking failures down by bearing — they should cluster on the landward arc.

Q204Whole file

Radial Count · QARTOD Test 9

Did the file produce enough vectors to be usable?

Below min_count the coverage is too sparse to trust and the file should not feed total-vector processing. Catches sick receivers, interference, and poor sea state.

min_count — fail below this
low_count — suspect below this
Count what the test counts

The test does not use the row count. When a VFLG column exists it counts only rows where VFLG != 128. For ISCY that is 421 of 453 rows. Thresholds derived from total rows are systematically too high — an early pass at this failed every ISCY file before the mistake was caught.

Q205Per row

Spatial Median · QARTOD Test 10

Does this vector agree with its neighbours?

Real ocean currents are spatially coherent — adjacent cells move similarly. Each vector is compared against the median of its neighbours. Catches isolated outliers that survive Q202 because they are individually plausible but wrong in context.

smed_range_cell_limit  — neighbourhood depth in range cells
smed_angular_limit      — neighbourhood width in degrees
smed_current_difference — max deviation from median (cm/s)

The angular window is scaled to each site's %AngularResolution. A fixed 10° spans about two neighbours at a 5° site but roughly twenty at a 1° site — very different tests wearing the same number.

Q206Per row

Temporal Gradient · QARTOD Test 11

Did this cell change too fast since last hour?

Currents have inertia; a 50 cm/s swing in an hour is not oceanography. This is the only test needing a second file — the previous hour, which qc_radial_file() locates by name in the same directory.

gradient_temp_warn — suspect above this (cm/s·hr)
gradient_temp_fail — fail above this (cm/s·hr)
Provisional

These are the only thresholds not derived from your data. Doing so needs a paired-consecutive-hour analysis that has not been run; the QARTOD manual defaults are in place meanwhile. Q206 is excluded from PRIM, so this does not affect filtering.

Expect a healthy share of 2 flags: cells with no counterpart last hour cannot be compared. All-2 means the previous file was not found.

Q207Whole file

Average Radial Bearing · QARTOD Test 12

Is the antenna still pointing where it should?

Averages the BEAR column and compares against a reference. Catches a knocked or drifting antenna and a degrading pattern.

reference_bearing  — expected mean bearing (deg)
warning_threshold  — suspect beyond this deviation
failure_threshold  — fail beyond this deviation

Do not use %AntennaBearing as the reference. The direction the antenna is aimed and the centroid of where it returns data are different numbers, because coverage is not symmetric about the boresight — land blocks one side. Across these sites they disagree by up to 106°.

The test measures constancy, not correctness, so thresholds follow each site's own hour-to-hour variability rather than a fixed 15/30. PCYC|IdealPattern is steady at σ = 4.0° and deserves tight bounds; OBSP swings at σ = 41° and would drown in false alarms.

Broken on full-circle sites

The library averages bearings arithmetically. Where coverage wraps through 0/360° that is not a real direction — for one Ideal-pattern site the arithmetic mean read 192° against a true circular mean of 351°. Sites failing that check have Q207 omitted entirely rather than given a meaningless reference.

Switching tests on and off

One table in qc_config.py · applied at run time

Every test carries two independent booleans. They are read by qc_walk.py when it runs, not baked into site_thresholds.py, so changing either takes effect immediately with no regeneration. 

TESTS = {
    "qc_qartod_syntax":             dict(run=True,  prim=True),   # Q201
    "qc_qartod_maximum_velocity":   dict(run=True,  prim=True),   # Q202
    "qc_qartod_valid_location":     dict(run=True,  prim=True),   # Q203
    "qc_qartod_radial_count":       dict(run=True,  prim=True),   # Q204
    "qc_qartod_spatial_median":     dict(run=True,  prim=True),   # Q205
    "qc_qartod_temporal_gradient":  dict(run=True,  prim=False),  # Q206
    "qc_qartod_avg_radial_bearing": dict(run=False, prim=False),  # Q207
}
  • run — run the test at all. False writes no flag column for it.
  • prim — let its result feed PRIM, the column you filter on.

run=True, prim=False records a flag for diagnosis without letting it condemn individual vectors. Parameters are derived for disabled tests anyway, so switching one back on also needs no regeneration.

Q201 and Q203 cannot be disabled

qc_radial_file calls qc_qartod_syntax() unconditionally (radials.py:147) and calls qc_qartod_valid_location() in an else branch when given no parameters (radials.py:153-157). Setting run=False on either is refused at import rather than silently ignored.

The table is validated when qc_config.py loads, so a contradiction stops the run before any file is touched. It rejects prim=True with run=False, non-boolean values, missing keys, disabling a non-optional test, and a table where nothing feeds PRIM. That last pair matters because qc_qartod_primary_flag silently ignores names for tests that did not run — an unnoticed contradiction would produce a PRIM column that looks correct and quietly omits a test.

For a single run, without editing the file:

python qc_walk.py --no-test qc_qartod_avg_radial_bearing

Safe to use freely — each output file records which tests actually ran in its own %QCTest header, so the provenance survives the flag being forgotten.

The PRIM rollup

The column you actually filter on

PRIM is the worst flag across the tests whose prim is True. A row with Q203 = 4 gets PRIM = 4 even though every other test passed it.

Q206 and Q207 are deliberately excluded. Q207 is a whole-file verdict about the instrument — a bearing failure should not condemn every individual vector. Q206 is coverage-dependent and produces 2 flags for reasons unrelated to data quality. Expect rows where Q206 = 4 but PRIM = 1.

Each file states its own membership, so the rollup is auditable after the fact: 

%QCTest: qc_qartod_primary_flag (PRIM) - Primary Flag - Highest flag value of
         Q201, Q202, Q203, Q204, Q205 ("not_evaluated" flag results ignored)

To filter, keep everything that is not a failure:

clean = r.data[r.data["PRIM"] != 4]

How the parameters were derived

Policy lives in qc_config.py · numbers are generated

Every number in site_thresholds.py comes from a percentile of what each site actually produced over the calibration window. The rules are policy choices, stated so they can be argued with:

ParameterRuleReasoning
Q202 high_speed p99 |VELO| The top 1% of observed speeds are worth a second look.
Q202 max_speed min(p99.9, velLimit) The radar cannot report past its own limit.
Q204 min_count p02 of VFLG≠128 Must match the statistic the test computes.
Q204 low_count p10 of VFLG≠128 A percentile is a flag rate — see below.
Q205 angular_limit 5 × %AngularResolution Keeps the neighbourhood a comparable arc at 1°, 2° and 5° sites.
Q207 reference median per-file mean Empirical, not the header's %AntennaBearing.
Q207 warn / fail 2σ / 3σ Follows each site's own variability.
A percentile is a flag rate

Setting low_count at the 25th percentile means roughly 25% of that site's files come back 3 — by arithmetic, not because anything is wrong with them. The current setting is p10, giving about 10%. Lower it for fewer flags, raise it to surface every thin hour. This is an operational judgement, not something the data can settle.

Overriding a derived number

Precedence is derived → FIXED → OVERRIDES. FIXED applies to every site and merges parameter by parameter, so one can be pinned while the rest stay derived; OVERRIDES is keyed "<institution>|<SITE>|<Pattern>" and replaces a test's parameters wholesale. Both require a regeneration, and both annotate the generated entry so the substitution is visible later. 

FIXED = {
    "qc_qartod_maximum_velocity": dict(high_speed=100),   # max_speed stays derived
}

OVERRIDES = {
    "usm|OBSP|IdealPattern": {
        "qc_qartod_radial_count": dict(min_count=10, low_count=30),
    },
}

A value you supply is used verbatim: unlike a derived max_speed, it is not capped at the site's %CurrentVelocityLimit. Naming a test that has no derived parameters adds it, which is the only way to reach Q203's use_mask and res.

Parameters are checked before the run

Every resulting dict is validated against the real Radial method signatures — unknown names, missing required ones, and names qc_radial_file supplies itself. A typo fails at startup naming the parameter, rather than partway through a run after files have been written. This is the check that would have caught the radial_smed_* bug that started this work.

Keys are <institution>|<SITE>|<Pattern> — the institution is part of the key so two networks can use the same site code without colliding. Velocities in cm/s, counts in vectors, angles in degrees. Empty is the share of files containing zero radial rows — these fail Q204, which is intended. OBSP and SGRV sit at the Q204_ABSOLUTE_FLOOR of 10 because their normal output is genuinely sparse.

Two sites have only one pattern: usm|OBSP is Ideal-only and gerg|MBNP is Measured-only. Running with --pattern MeasPattern therefore skips OBSP, and --pattern IdealPattern skips MBNP.

No fallback for an unknown site

A site+pattern absent from this table is not processed. There are no default thresholds — flags computed against substitute numbers would look valid and mean nothing. Such sites are listed before the run, marked no thresholds in the progress table, listed again in the summary, and make the exit status 1. Adding a site means regenerating site_thresholds.py, not just dropping files into LOCAL_BASE.

Running it

Four files in qartod/ · run from inside it

FileRoleHand-edit?
qc_config.pyPolicy — percentiles, test switches, FIXED, OVERRIDESYes — this is the one you tune
gen_thresholds.pySurveys raw files, emits thresholdsOnly to change the survey itself
site_thresholds.pyThe derived numbersNo — regenerated; use FIXED / OVERRIDES
qc_walk.pyWalks raw/ → qartod/Rarely

Typical cycle

cd qartod

# 1. adjust policy (e.g. Q204_LOW_PERCENTILE)
$EDITOR qc_config.py

# 2. regenerate the numbers    ← only after a percentile, sigma rule,
python gen_thresholds.py \       FIXED, OVERRIDES, or a new site
    > site_thresholds.py

# 3. see what would happen — writes nothing
python qc_walk.py --dry-run

# 4. trial one site into a scratch root
python qc_walk.py --site ISCY --limit 24 --out /tmp/trial

# 5. the real run
python qc_walk.py

# ...or one antenna pattern at a time
python qc_walk.py --pattern MeasPattern
python qc_walk.py --pattern IdealPattern

Step 2 is conditional. Changing TESTS takes effect immediately, since qc_walk.py reads it at run time. It is required when a site is new.

Reruns skip existing outputs, so step 5 is resumable; pass --force to redo. Per-file failures are counted and reported without aborting the run.

The redirect in step 2 is load-bearing

gen_thresholds.py prints the module to stdout rather than writing the file. Run it bare and the thresholds scroll past while site_thresholds.py stays untouched — silently, with no error. Run it from the repo root and the file lands where nothing imports it, leaving the real one stale. If a change to qc_config.py seems to have had no effect, check this first.

Environment

Requires pandas < 3. Under pandas 3 to_ruv() raises TypeError: Invalid value '%%' for dtype 'float64' and leaves a truncated file on disk. The pin is applied to the conda environment only — environment_dev.yml is unchanged. Under pandas 2 the same line emits a FutureWarning once per file; that warning is the pin's expiry notice.

Decisions and why

The reasoning behind non-obvious choices

Measured over Ideal, where both exist

Ideal-pattern files span the full compass, which breaks Q207's arithmetic mean and inflates Q203 failures. Measured patterns cover a narrower, real arc. Ten of the eleven sites have both; OBSP has only Ideal.

QC Ideal and Measured separately

They are two different processings of the same measurement hour, and their statistics differ substantially — SGRV has 23% empty files on Ideal against 4% on Measured. Pooling them produces thresholds that fit neither.

Q207 omitted rather than approximated

Where σ exceeds 20° or the arithmetic and circular means disagree by more than 15°, no reference bearing would be meaningful. A test that cannot work is better left out than given a number that looks authoritative.

Empty files are QC'd, not skipped

A file with zero radial rows is a real operational signal. It flows through and fails Q204, which is the correct record. HBSP at 22–25% empty is worth investigating on its own.

Unconfigured sites are skipped, not defaulted

An earlier version fell back to generic thresholds for a site with no entry. That produced output that looked valid and meant nothing, and — because reruns skip existing files — a later regeneration would not repair it. Removing the fallback makes adding a site a deliberate two-step act: drop the files in, then regenerate. The data alone produces nothing.

Test switches are read at run time

Whether a test runs, and whether it feeds PRIM, needs no knowledge of the data — so baking it into site_thresholds.py would mean surveying 11,791 files to flip a boolean. Keeping it in qc_config.TESTS and applying it at run time also leaves site_thresholds.py holding only measured facts, and qc_config.py only chosen ones.

Unfinished work

  • Q206 thresholds are not derived — needs a paired-hour analysis.
  • One month is a thin calibration window. The percentiles assume most of 2026-07-23 → 08-17 was healthy. If a site was faulty in that period, the thresholds have been calibrated to accept the fault.
  • Flag rates have not been reviewed at full scale. A 168-file trial across four sites gave PRIM pass rates of 58–99% with zero errors, but the full 11,791-file run has not been made.
  • Nothing verifies the output. No pass checks that a written file's %TableRows matches its actual row count, or flags files whose Q205 column is uniformly 2 — the two signatures of an interrupted run.
